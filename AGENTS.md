# AGENTS.md — `Archont561/workloop`

Repository instructions for AI coding agents (`goose`, `opencode`, `claude`, `pi`, `codex`, `aider`, and custom OpenAI-compatible CLIs). Keep this file concise, authoritative, and synced with `CLAUDE.md` (symlinked to `AGENTS.md`).

## 1. Mission & Scope

`workloop` is an ecosystem-agnostic, agent-agnostic, reviewer-agnostic Rust CLI that runs a zero-cost AI feature delivery loop on GitHub powered by free open models and free cloud tiers:

`task -> PR -> review & green checks -> repair -> merge -> next task -> human approval -> release`

At scaffold version `0.1.0` (`m-0`), `crates/workloop-core` and `crates/workloop` implement canonical version/help handling and `clifacet` (`0.5.0`) credential redaction, while [`backlog/`](backlog/README.md) tracks `m-1` (localhost OpenAI `429` failover proxy + `open`/`exec`/`verify`/`close` lifecycle) and `m-2` (`pool | github-bot | both | command` review gates + Stage-0/Stage-1 self-dogfooding).

**Hard design invariants:**

- **No built-in ecosystem presets.** Users declare arbitrary shell hooks (`setup`, `next_task`, `gates`, `review`, `merge`, `release`) in `workloop.toml` — for example `setup = "sh scripts/restore.sh"`.
- **Orchestrator-decoupled CLI.** Never generate or couple to `.archon/` YAML templates; expose standalone UNIX verbs (`open`, `exec`, `verify`, `close`) built on `clifacet`.
- **No single-agent or single-reviewer lock-in.** Any CLI coding agent runs unmodified behind `workloop exec` via localhost `OPENAI_BASE_URL`, and review supports distinct-family `pool` models as well as optional `github-bot` (CodeRabbit), `both`, or `command`.
- **Centralized `doit` automation.** All Python tasks live in `tools/dodo.py` configured by root `doit.cfg` (`dodoFile = tools/dodo.py`, `cwdPath = .`), with Gherkin specs in `tools/features/` and tests in `tools/tests/`. Never create a root `dodo.py`.
- **Strict `>= 90%` coverage.** Enforced across both Rust (`crates/*/src/` via `cargo-llvm-cov` + `tools/coverage_gate.py`) and Python (`tools/` via `.coveragerc`), and mirrored in `codecov.yml`.

## 2. Repository Layout

- `crates/workloop-core/` — Pure Rust domain library (`src/`, `features/`, `tests/`). Zero CLI/TUI dependencies.
- `crates/workloop/` — Standalone CLI binary (`clifacet = "0.5.0"`), `pyproject.toml` (`maturin`), and Conda recipe (`crates/workloop/recipe/{recipe.yaml,variants.yaml}`).
- `registry/free-models.json` — Verified free tool-calling open-model registry and distinct-family default pools.
- `tools/` — Centralized `doit` task graph (`dodo.py`), policy/prose/version/coverage checks, `features/*.feature`, and `tests/*.py`.
- `backlog/` — `backlog.md` (`1.55.3`) config, specification, ADRs (`decision-1`..`decision-8`), milestones (`m-0`..`m-2`), and tasks (`WKL-001`..`WKL-004`).
- `docs/` — Canonical architecture, concept, guide, and reference pages (`docs/README.md`).
- `scripts/` — `restore.sh` (generated by `pixi-sandbox init`), `bootstrap.sh`, and `install_hooks.sh`.
- `.agents/skills/` & `skills-lock.json` — Locked upstream skills plus local `session` and `regain-direction` skills.

## 3. Canonical Commands

Always run verification through locked Pixi tasks (`pixi.toml`):

```sh
# Bootstrap / hooks
pixi install --locked
pixi run --locked bun-install
pixi run --locked install-hooks

# Structural, prose & policy gates
pixi run --locked alint
pixi run --locked sandbox-check
pixi run --locked automation check_policy
pixi run --locked automation lint_prose
pixi run --locked docs-lint
pixi run --locked check-links-offline
pixi run --locked lint-toml
pixi run --locked actionlint

# Python tools/ gates (>= 90% coverage)
pixi run --locked lint-python
pixi run --locked format-python-check
pixi run --locked typecheck
pixi run --locked test-tools-cov

# Rust crates/ gates (>= 90% coverage)
pixi run --locked fmt-check
pixi run --locked clippy
pixi run --locked test-all
pixi run --locked coverage
```

## 4. Workflow Rules for Agents

1. **Start with `.agents/skills/session/SKILL.md`.** Survey `backlog/` (`pixi run --locked backlog task list --plain`) before editing code.
2. **Spec-first BDD.** Add or update a `.feature` scenario (`crates/*/features/` or `tools/features/`) before changing observable behavior; lint Gherkin via `pixi run --locked automation lint_gherkin`.
3. **Generated files.** Edit `.readme/README.template.md` (regenerate via `pixi run --locked readme`), `vale.toml` (regenerate via `pixi run --locked automation prose_sync`), `pixi-sandbox.toml` (regenerate via `pixi-sandbox init`), and Conventional Commits (`pixi run --locked automation changelog`) rather than hand-editing generated outputs.
4. **Conventional Commits.** Format every commit message as `<type>(<scope>): <summary>` so `convco` and `lefthook` pass cleanly.
